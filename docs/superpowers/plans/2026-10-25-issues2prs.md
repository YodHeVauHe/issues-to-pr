# issues2PRs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish a cross-runtime skill that turns GitHub issue(s) into PR(s) by bootstrapping superpowers when missing and then handing off to the untouched superpowers flow.

**Architecture:** A single SKILL.md orchestrator plus one reference file (`references/runtime-detection.md`) for per-runtime skill paths, detection, and install. No code — the skill is process documentation, tested with subagent pressure scenarios per writing-skills (RED → GREEN → REFACTOR), then published as a plain skill repo installable via `npx skills add`.

**Tech Stack:** Markdown (agentskills.io SKILL.md format), `gh` CLI, `npx skills` CLI, subagent testing via the Agent tool.

**Spec:** `docs/superpowers/specs/2026-10-25-issues2prs-design.md`

## Global Constraints

- SKILL.md frontmatter `name` is exactly `issues2prs`; repo/repo name is `issues2PRs`
- Description in frontmatter: third person, starts with "Use when", under 1024 characters
- The skill must never instruct skipping or interrupting brainstorming, plan approval, or review gates
- MIT license (already in repo), copyright "YodHeVauHe"
- Only tools the skill may invoke: `gh`, `npx skills`, git, standard shell — no other dependencies
- Baseline/pressure tests dispatch subagents with the skill text pasted into the prompt (subagents cannot hot-load new skills)
- Nothing secret in the repo; it is public

## Review Focus

Spec-implied failure modes the happy-path tests don't cover; each pinned to its owning task:

1. **User pressure to skip process** ("just fix it fast, skip the ceremony") — skill must hold the brainstorming/plan gates. Test: Task 4, Step 1 scenario.
2. **Superpowers already installed** — must detect and continue, not reinstall. Test: Task 4, Step 2 scenario.
3. **Agent not in the issue's repo** (or in no repo) — must clone the issue's repo before branching. Test: Task 4, Step 3 scenario.
4. **No push access to origin** — must fork, push the fork, and PR with `--head`. Test: Task 4, Step 4 scenario.
5. **Newly installed skills not hot-loadable mid-session** — must fall back to reading the skill files from disk and following them. Test: Task 4, Step 5 scenario.

### Task 2: Write the skill (GREEN)

**Files:**
- Create: `references/runtime-detection.md`
- Create: `SKILL.md`

**Interfaces:**
- Consumes: `docs/testing/2026-10-25-baseline.md` (each observed failure gets explicit guidance)
- Produces: `SKILL.md` with frontmatter `name: issues2prs` and the pinned description below; `references/runtime-detection.md` with the paths/detection/install table SKILL.md links to

- [ ] **Step 1: Write `references/runtime-detection.md`**

A table with one row per runtime — Claude Code `~/.claude/skills/`, ZCode `~/.zcode/skills/`, Codex `~/.codex/skills/`, cross-runtime alias `~/.agents/skills/` — plus: detection method (look for `using-superpowers/SKILL.md` under each path; superpowers is present if any hit), install command `npx skills add https://github.com/obra/superpowers`, verify-then-fallback rule (if the harness's skill list doesn't show the new skills this session, locate them on disk and Read/follow the SKILL.md files directly), and the note that skill-name prefixes vary by runtime (e.g. `superpowers:brainstorming` vs `brainstorming`).

- [ ] **Step 2: Write `SKILL.md`**

Frontmatter exactly:

```yaml
---
name: issues2prs
description: Use when the user wants GitHub issue(s) turned into pull request(s) — fixing, implementing, or addressing an issue and opening a PR for it, whether or not the superpowers skills are installed yet. Triggers on requests like "fix issue #N and open a PR", "turn these issues into PRs", or an issue URL plus a PR request.
---
```

Body sections (order fixed): Overview (one paragraph: bootstrap superpowers, fetch the issue, hand off to the normal interactive superpowers flow, land the PR); Preflight (ensure superpowers per references/runtime-detection.md; `gh auth status`, and if it fails tell the human to run `gh auth login` before continuing); Read the issues (`gh issue view N --repo OWNER/REPO --json number,title,body,labels,comments,url`); Get into the repo (already in the issue's checkout → use it; otherwise clone it); Per issue, in order (isolated branch named `issue-N-short-slug`; enter the normal superpowers flow with the issue as input — brainstorming with the human, writing-plans, TDD execution, requesting-code-review, finishing-a-development-branch — each invoked exactly as that skill directs, never shortened); Land it (push origin, or fork first with `gh repo fork` if push denied, then `gh pr create` with body containing `Closes #N`); Report (PR URL per issue) and stop — never merge, never self-review away the gates. A short rationalization table answering each baseline failure from Task 1.

- [ ] **Step 3: GREEN test — re-run scenarios A, B, C with the skill**

Dispatch the same three subagent scenarios, this time pasting SKILL.md and references/runtime-detection.md content into the prompt as "you have this skill installed". Compliance checklist per scenario: mentions ensuring superpowers (or its presence), asks the human questions before implementing (brainstorming), one branch per issue, PR body has "Closes #N", does not merge, batch is sequential. All six checks × 3 scenarios must pass.
